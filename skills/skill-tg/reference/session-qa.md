# Сессия как инструмент проверки/QA

Та же Telethon user-сессия, что снимает чужие боты (см. recon.md), — наш способ **проверять
информацию и QA-ить свой бот вживую**, без ручного тыканья телефоном. Один процесс за раз на .session.

## Что через неё проверяем
- **Свой бот после деплоя**: прогнать экран (`/start` → клики) и снять текст+кнопки → убедиться, что
  правки применились, стили/эмодзи на месте, ничего не упало. То же самое, что recon, но `get_entity`
  указывает на НАШ бот (по его id/username).
- **Свой telegram_id и данные аккаунта**: `me = await client.get_me()` → `me.id`, `me.username`,
  `me.premium`. Нужен, например, чтобы выдать что-то на реальный аккаунт или проверить наличие Premium.
- **Живые данные апстрима**: дернуть партнёрский API из окружения бота (цены split, баланс the VPN partner,
  Dynadot) и сверить с тем, что бот показывает.
- **Разведка чужих цен/меню** — recon.md.

## Паттерн: снять экран своего бота
```python
ent = await client.get_entity(<OUR_BOT_ID>)      # свой бот по id
await client.send_message(ent, "/start")
await asyncio.sleep(2.5)
m = await newest(client, ent)                     # newest() из recon.md
dump(m)                                           # текст + кнопки + стиль + иконки
# пройти вглубь:
await click(client, ent, b"some:callback"); await asyncio.sleep(2); dump(await newest(client, ent))
```
Смотри именно `reply_markup` (стиль/иконки кнопок) и `entities` (кастом-эмодзи-ids) — так проверяешь,
что премиум-оформление реально ушло в Telegram, а не только в коде.

## Ловушка стилей кнопок
Если у бота **периодически пропадают цвета кнопок** — почти всегда это **дубликат процесса бота**
(например забытый `nohup python bot.py`), который дерётся с systemd за `getUpdates`. Один инстанс
отдаёт стили, другой нет → мигание. Убей дубликаты, оставь один сервис.

## Проверка через окружение бота (не только UI)
Иногда быстрее проверить логику напрямую на сервере, с загруженным `.env`:
```bash
ssh server 'cd /root/app && set -a; . ./.env; set +a; ./venv/bin/python -c "
import asyncio, config, split_api as s
print(asyncio.run(s.balance()))            # живой баланс/цена из окружения бота
"'
```
Так ловишь расхождения «код ↔ .env ↔ апстрим» (напр. курс/наценка берётся из .env, а не из дефолта кода).

## Дисциплина
- **Один процесс на .session** за раз. Свой бот при этом может работать (это другой аккаунт — бот, а
  не user-сессия).
- Драйвер — файлом + `scp`, не heredoc.
- Не спамь: между кликами ~2с; свой бот флуд-лимит не бьёт, но чужой — да.
